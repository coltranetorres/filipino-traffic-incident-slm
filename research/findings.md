# Findings: small language models for Filipino/Taglish traffic incident extraction

Status: test split scored once per configuration (nine runs). Single seed, synthetic data. The result tables below
are produced from `experiments/<run>/results*.json`, `meta*.json` and `data/processed/MANIFEST.json` by
`scripts/make_findings_tables.py` (run `uv run python scripts/make_findings_tables.py` from the repo root).
Scores are shown as `value [95% CI]`, rounded to 2 decimals. Numbers quoted in prose come from those tables, except:
the failure counts in limitation 8 (counted by running `parse_report` over the stored raw outputs, with hand-written
categories); class and language counts (`data/processed/MANIFEST.json`, table `data` of the script); iteration
counts and training times (`meta.json`); and the post-hoc numbers in sections 2, 4.2, 4.7 and 7, which come from
`results/alias_sensitivity_test.md`, `results/posthoc_metrics_test.md` and `results/leakage_check.md`
(generated by scripts named there).

Related work: to be added after reading primary sources.

## 1. Question and hypothesis

Research question (design, section 1):

> Can a relatively small language model (1-4B parameters), fine-tuned on Filipino, English, and Taglish traffic incident reports, achieve structured incident understanding while remaining efficient enough to run locally?

Hypothesis (design, section 2, stated before experiments ran):

> LoRA fine-tuning a small model on a domain-specific Filipino/Taglish traffic dataset improves structured incident classification and location extraction over zero-shot and few-shot prompting of the same model, while keeping inference cost low enough to run locally.

"Reliable" is not defined as a pass/fail threshold, because no threshold could be justified in advance. This document
therefore claims no yes/no verdict. It reports separate scores per task with confidence intervals and states which
comparisons the intervals do and do not separate.

Similarity check (post-hoc, computed after scoring; not used for any selection; `results/leakage_check.md`): between
the 176 test texts and the 207 train texts there is no exact duplicate; the highest SequenceMatcher ratio is 0.69
(te-165 vs tr-087), no pair exceeds 0.7, and the highest word-token Jaccard is 0.50 (te-062 vs tr-079). Against
validation the maxima are 0.68 and 0.39. This is a surface-similarity check; it is not proof that test scenarios are
independent of training scenarios.

Label taxonomy (`docs/annotation-guidelines.md`): `incident_type` is one of vehicle_breakdown, road_accident,
road_hazard, flooding, road_closure, heavy_traffic, other, unknown. `severity` (low/medium/high/unknown) is based on
reported impact only, `road_obstruction` is none/partial/full/unknown, `language` is filipino/english/taglish, and the
location fields road, landmark and direction may be null. For contradictory reports the primary incident type is kept
and any contradicted field is `unknown`.

Language-label rule (owner's): all-English text is `english`; any English word (excluding road, street and place
names) mixed with Filipino is `taglish`; no English words is `filipino`. Words spelled like English (bus, jeep, lane,
motor) count as English.

Test subsets (an item can carry more than one tag): noisy n=26, no_location n=9, short n=10, ambiguous n=18,
contradictory n=10. Language groups: filipino n=38, taglish n=110, english n=28.

## 3. Method

**Models.** Gemma 3 1B (`mlx-community/gemma-3-1b-it-bf16`) and Qwen2.5 1.5B Instruct
(`mlx-community/Qwen2.5-1.5B-Instruct-bf16`), 16-bit weights, run with MLX on a MacBook M4 (24 GB). Greedy decoding,
`max_tokens` 200 (`experiments/models.json`, `meta*.json`).

**Prompting baselines.** Zero-shot and few-shot use one fixed prompt with the output schema; no prompt tuning.
Few-shot uses k=5 examples from the train split (ids tr-204, tr-139, tr-117, tr-104, tr-064; the same five for both
models).

**LoRA.** Trained with `mlx_lm lora` on the train split: batch size 4, learning rate 1e-5, 16 layers, 3 epochs
(156 iterations for n=207), `mask_prompt` on, max sequence length 1024, seed 0 (`meta.json`). The iteration count
scales with n (39 at n=50, 75 at n=100, 156 at n=207). Training wall time for n=207: Gemma 181 s, Qwen 236 s,
Gemma 4-bit 202 s.

**4-bit comparison.** The same LoRA recipe on `mlx-community/gemma-3-1b-it-4bit`.

**Data-size sweep.** Gemma 3 1B (16-bit) trained on 50, 100 and 207 items. The 50 and 100 subsets are
class-balanced (50: 6-7 per class; 100: 12-13 per class, counted from each run's `mlx_data/train.jsonl`).

**Seeds.** One seed (0) for everything. No variance across seeds was measured.

**Metrics** (computed in `src/trafficslm/`; an output that does not parse or match the schema counts as wrong on every
metric):

- Incident macro-F1: macro-averaged F1 over the incident classes present in the gold labels of the (sub)set being
  scored; "no unknown" drops `unknown` from the average. In a subset, a class that is only predicted (never in the
  gold labels of that subset) is therefore not averaged in, and its false positives do not enter the score.
- Severity, obstruction and language accuracy: exact match with the gold label.
- Location F1: field-level F1 over road, landmark and direction after normalization (case, spacing, alias list such
  as EDSA = Epifanio de los Santos Avenue). In the F1, a field that is null in both gold and prediction is neutral
  (it counts as neither a match nor an error); a non-null prediction for a null gold field is a false positive. In the
  per-field location accuracies (road, landmark, direction), null predicted for null gold counts as correct. If gold
  and prediction have no non-null field at all, F1 is defined as 1.0. The alias list is deliberately short
  (`data/aliases.json`); see limitation 13 and section 4.7 for its effect.
- Post-hoc metrics that are NOT in the pre-registered list: severity macro-F1 and per-class incident precision,
  recall and F1 (section 4.7). They were computed after scoring, from the stored predictions, and were not used for
  any selection.
- JSON validity: share of outputs that parse to the schema (first balanced object, code fences stripped).
- Abstention: share of gold-null location fields that the model correctly left null.
- 95% CIs: bootstrap over items, 1000 resamples, seed 0. They reflect test-item sampling only, not seeds or
  training-set choice.

**Protocol.** Model selection used validation only (n=40) and was written down in `research/selection.md` before any
test run, including the list of nine configurations. Each configuration was scored once on the test split (n=176);
no model, prompt or hyperparameter was changed afterwards. Each test run used its own process, so reported peak
memory is a per-process peak.

interval check. For Gemma the intervals stay separate (0.72 vs 0.23 with extended aliases). The pre-registered
numbers stay in the tables above.

### 4.4 Gemma vs Qwen

On validation Gemma n207 was ahead on incident macro-F1 (0.77 [0.58, 0.90] vs 0.60 [0.38, 0.74]), severity
(0.72 vs 0.62) and obstruction (0.78 vs 0.55). On test the order reversed on those three
(0.61 vs 0.64, 0.48 vs 0.52, 0.55 vs 0.57), and Qwen is higher on language (0.85 [0.79, 0.90] vs 0.77 [0.71, 0.83])
and location F1 (0.79 [0.74, 0.84] vs 0.72 [0.66, 0.77]). Every Gemma-vs-Qwen interval overlaps on every task, on
both splits. No winner is claimed. On cost, Gemma is smaller and faster: median latency 643 ms vs 861 ms and peak
memory 3.15 GB vs 3.71 GB (test, per process).

## 5. Subset analysis (test)

### 5.8 Observations, with their limits

- Taglish (n=110) is the largest group. LoRA improves incident macro-F1 over few-shot for both models (Gemma 0.21 to
  0.58, Qwen 0.48 to 0.66); the Gemma intervals are separate, the Qwen intervals overlap slightly.
- Language accuracy by language group is uneven. Qwen few-shot is 0.97 on taglish but 0.03 on filipino and 0.11 on
  english; Qwen LoRA is 0.76 on filipino, 0.86 on taglish and 0.89 on english. Gemma LoRA is 0.34 on filipino against
  0.88 on taglish and 0.93 on english. Because the filipino/taglish boundary depends on the owner's rule (section 7),
  part of this difference may come from the rule rather than the model; this was not tested.
- Contradictory (n=10): severity and obstruction accuracy of the LoRA models are 0.10 or 0.00. The gold value for a
  contradicted field is `unknown`, and in the example below the model gave a concrete value; whether that is the
  general pattern was not checked. Example (`te-025`, gold road_accident, severity unknown, obstruction unknown):
  "Minor lang daw ang banggaan sa C5 pero buong kalsada ay sarado". Qwen LoRA predicted road_closure, severity
  medium, obstruction partial. In the same subset incident macro-F1 is 0.83 for both LoRA models. With n=10 these are
  descriptive only.
- `te-024` ("Light traffic daw sa Shaw pero di gumagalaw ang mga sasakyan", gold heavy_traffic, severity and
  obstruction unknown): Qwen LoRA predicted heavy_traffic with severity medium and obstruction none, and put
  "Shaw Boulevard" in the landmark field instead of road. This is one example, not a rate.
- No_location (n=9) and short (n=10): intervals span 0.4 or more on most metrics. No conclusion is drawn.
- Abstention is high for both LoRA models across subsets (0.83 to 1.00 in the table). For few-shot Gemma it is low
  (0.11 to 0.59), mixed with format failures.

Summary: on this synthetic test set, LoRA fine-tuning of both models raises JSON validity to 0.99 and gives clear gains
over few-shot prompting on most tasks where the baseline produces valid output (for Qwen location, the gain depends on alias coverage, section 4.7). Absolute severity and obstruction
accuracy remain around 0.5 to 0.6, incident macro-F1 around 0.6, language accuracy 0.77 to 0.85. The data does not rank
the two models, does not show that every task benefits from more training data, and shows lower (not statistically
separated) accuracy for the 4-bit model at about 60% of the latency and 42% of the memory. Whether these levels are
sufficient is left to the reader.

## 7. Limitations

1. **Synthetic data.** The assistant drafted all items, and even after the owner's edits they may keep the assistant's
   phrasing and structure. Scores may not transfer to real reports, which can be messier and more varied. No real
   reports were tested.
2. **Small training set.** 207 items, below the roughly 400 originally planned; the sweep stops at 207.
3. **Single seed.** No variance from training seed, data order or subset choice is estimated. The CIs capture
   test-item sampling only, so differences of a few points between runs may be within seed noise.
4. **Small subsets.** Many subset cells have n of 9 to 28; contradictory, short and no_location have n of 9 to 10.
5. **Language labels follow an owner-defined rule.** Loanwords such as bus, jeep, lane and motor count as English, so
   a sentence that a Filipino speaker would call Filipino can be labelled taglish. The language breakdown and the
   language accuracy figures are partly a product of that rule. Train item tr-110 ("Hindi gumagana ang ilaw trapiko sa
   kanto ng Kalayaan at Buendia") is labelled taglish but contains no English-spelled word, so it is a suspected
   language mislabel; it is kept as is (the training data is checksummed and the models were trained on it) and is
   flagged for the label-noise follow-up. Also, the system prompt lists the language values but does not state the
   labelling rule (`src/trafficslm/prompts.py`), so baseline language accuracy partly reflects not knowing the rule.
6. **Open guideline points.** Severity cut-offs (flood depth, delay minutes), the effect of a stated detour on
   severity, and whether `heavy_traffic` with a stated cause belongs in that class are still marked open in
   `docs/annotation-guidelines.md`. Severity and obstruction labels depend on those choices, and relabelling could
   change the scores. A blind relabel of a sample to estimate label noise (design section 11) is not reported here.
7. **Untuned baselines.** Zero-shot and few-shot used one fixed prompt with no tuning, so those numbers are lower
   bounds on what prompting can reach.
8. **Gemma baseline output format (validation and test).** Gemma 3 1B zero-shot and few-shot are mostly counted
   invalid (test JSON validity 0.24 and 0.28). I ran the project's `parse_report` on the stored raw outputs and
   categorised the failures by hand-written rules; the counts are approximate.
   - Zero-shot: every raw output is code-fenced (the parser strips fences). On validation 27 of 40 fail; 21 of those
     are sibling objects (several consecutive `{...}` objects holding different keys, so `parse_report`, which reads
     only the first object, misses severity, obstruction and language), 4 have misplaced or missing keys and 2 fail on
     a schema value or extra key. On test 134 of 176 fail: 99 sibling-object splits, 12 misplaced or missing keys,
     23 schema value or extra-key failures (for example a `direction` key outside `location`, `te-006`).
   - Few-shot: no fences, no multi-object outputs. On validation 24 of 40 fail: 7 unterminated or no balanced object,
     9 missing keys, 6 schema failures, 2 prose. On test 126 of 176 fail: 47 unterminated or unbalanced, 41 missing
     keys, 35 schema failures (for example an extra `details` key or the misspelled value "Nortbound"), 1 malformed
     JSON, 2 prose. Separately, 65 of the 176 test raws fail plain `json.loads`, and 63 of those end with a closing
     brace, so they are malformed rather than cut off; the other failures are valid JSON that fails the schema.
   - The checked failures were not truncation. Why the models produce these formats was not tested.
9. **No 4B comparison.** The optional Gemma 3 4B comparison from the design was skipped, so the "1-4B" range in the
   research question is covered only at 1B and 1.5B.
10. **Data-size subsets differ in class mix.** The n=50 and n=100 subsets are class-balanced (6-7 and 12-13 items per
    class), while the full train split is not (for example road_accident 37, other 14, unknown 16). The curve
    therefore changes class mix as well as size. The subsets are nested (the n=50 item ids are contained in the n=100
    ids, which are contained in the 207 train ids; checked by regenerating the subsets with `stratified_subset`, seed 0),
    so the curve adds data rather than swapping it.
11. **Paired comparisons not run.** All runs score the same test items, so a paired bootstrap would be tighter than
    the interval-overlap checks used here. It was not computed.
12. **Single machine.** Latency and memory are from one MacBook M4, one run each, with no variance estimate.
13. **Alias coverage.** The road-name alias list used for scoring (`data/aliases.json`, fixed before testing) maps
    some bare names (Taft, Katipunan, Aurora, Roxas) but not others (Commonwealth, Shaw, Recto, Ortigas, Marcos,
    Kalayaan, McArthur). Models that write a short form are therefore penalised on some items, which lowers the
    prompted baselines more than the fine-tuned models. The post-hoc re-scoring in section 4.7 changes Qwen few-shot
    location F1 from 0.64 to 0.70 and Qwen LoRA from 0.79 to 0.80, and removes the interval separation between the two
    for Qwen. Other variants (for example landmark spellings) may remain uncovered. The pre-registered scores were not
    changed.
14. **Post-hoc metrics.** Severity macro-F1, per-class incident scores, the alias sensitivity table and the similarity
    check were computed after the test scores were known and were not part of the pre-registered metric list. They are
    descriptive and were not used to choose anything.

## 8. Next steps (ranked)

1. Add more and more diverse training data, and collect real permissioned reports as a second test set. This addresses
   the largest limits (synthetic text, small training set).
2. Run multiple seeds for the main configurations (and for the n=100 vs n=207 severity result) to get a variance
   estimate.
3. Resolve the open guideline points, relabel, and estimate label noise with a blind relabel of a sample.
4. Try Gemma 3 4B or another larger model, as in the original plan.
5. Add prompt-tuned and constrained-decoding baselines to see how much of the LoRA gain a better prompt recovers.
6. Run paired bootstrap comparisons between runs on the same test items.
